### A. Verdict per critique point

**1. False precision — VALID. Severity: High.**
The weighted sum is arithmetically correct over inputs that are verbalized numbers with no calibration behind them. The literature is unambiguous: verbalized numeric confidence from LLMs is systematically miscalibrated and barely improves with prompting (Tian et al. 2023, *Just Ask for Calibration*; Xiong et al. 2024, *Can LLMs Express Their Uncertainty?* — verbalized confidence is near-random on hard items). Worse, the SKILL.md example calls it "78% confidence" — a category error on top of miscalibration, covered in section B. **Fix:** per-criterion behavioral anchors (e.g., `reversibility: 80–100 = revertible in <1h with no data migration; 40–79 = revertible with scripted rollback; 0–39 = destructive/irreversible`), map totals to 3–4 ordinal bands ("Strong lead / Contested / Weak field"), and never render a percentage. Cite the anchors in the SKILL.md so the same rubric text is in-context every scoring pass.

**2. Panel is not independent — VALID. Severity: High (given current labeling).**
Same-model self-role-play is the weakest form of "multi-agent" diversity. Du et al. 2023 (*Multiagent Debate*) showed gains, but subsequent work (Smit et al. 2024, *Should we be going MAD?*; Atil et al. 2025 on debate conformism) found homogeneous debate often fails to beat self-consistency sampling and converges to consensus without information gain. The diversity that matters is informational (different retrieval, different tools, different models), not persona adjectives. The system is not worthless — a forced "argue the opposite" pass does surface some neglected considerations — but "Panel pick —" framing launders one opinion as four. **Fix:** two-part. (a) Rename output to "Second-pass review" and drop the panel framing. (b) Make the voices structurally, not tonally, different: Skeptic must cite at least two concrete failure modes with file/line references; Pragmatist must produce an estimate of implementation effort; Critic must argue for the *lowest-scored* candidate. Identical persona-flavor text with no required evidence artifacts is the failure mode.

**3. Force-phrase substring matching — VALID. Severity: Medium.**
The model must already do NLU to *call* `should_escalate(user_message=...)` — it has to decide to pass the raw message. So the substring check adds zero NLU capability the host doesn't have, while adding false negatives ("can you get someone else to weigh in?") and false positives (user says "I don't want a second opinion, just pick" → panel triggers). This is keyword matching bolted onto an NLU system that then hands the NLU problem back to the keyword matcher. **Fix:** delete `user_forced_panel` and the `user_message` parameter. The signature becomes `should_escalate(ranked_scores, high_stakes, force_panel)` where `force_panel` is a boolean the model sets from its own reading of intent. Keep the phrase list in SKILL.md prose as *examples of escalation intent* for the model, not as a matching table.

**4. Tournament seeding defect — PARTIALLY VALID. Severity: Medium (real defects, wrong diagnosis).**
The specific claim is wrong. Round-robin distribution *is* standard bracket seeding — it's how #1 and #2 seeds are placed in opposite halves so they meet in the final, not a defect. And in this design `pick_fn` is the **user's** answer, not `max(score)`: #2 doesn't "die to a weaker field," it dies only if the user picks something else in its group, which is the user's expressed preference — the entire point of the exercise. The proposed fix (carry top-K by score) would be worse: it converts the tournament from user-driven elimination into the model pre-filtering on the very scores critique #1 just established are noise. The *actual* defects: (a) `simulate_to_single_winner`'s default `pick_fn=max(score)` makes the demo assert that #1 wins — trivially true under score-based picking, so it tests nothing; (b) no handling of the "Other" free-text escape: a user who types a new candidate mid-tournament injects an unscored option the protocol has no branch for; (c) question-count blowup — N=17 costs 8 AskUserQuestion rounds; (d) after round 1, `build_round` receives winners in group order, not score order, so the "ranks spread evenly" invariant silently breaks in later rounds. **Fix:** cap tournament depth (if N > 12, run rubric on all, then present only the top 8 in two bracket rounds, with an explicit "a full bracket of 17 would take 8 rounds — showing top 8 by score, ask for full bracket if you want the rest" line); require re-scoring of any "Other"-introduced candidate before it enters a bracket; sort winners by score between rounds.

**5. No range enforcement — VALID. Severity: Medium.**
`score_choice({"fit_to_constraints": 0.9, ...})` yields a confident-looking 39.2 total; a 150 silently inflates. Also unnamed: `score_choice` ignores *extra* keys, so a typo'd criterion name fails loudly (missing key) but a misspelled *duplicate* passes silently, and non-numeric values raise `TypeError` far from the cause. **Fix:** in `score_choice`, validate `set(sub_scores) == set(CRITERIA_WEIGHTS)` and `all(isinstance(v, (int, float)) and 0 <= v <= 100 for v in sub_scores.values())`, raise `ValueError` naming the offending key/value. Five lines.

**6. Zero integration testing — VALID. Severity: Critical.**
This is the only failure mode that matters. A skill is a prompt; its unit of correctness is "did the agent follow the protocol in a live session," and nothing in the repo tests that. Pure-function demos testing `sorted()` and `abs()` are theater. This is also standard practice now — prompt/agent evals are a solved tooling category (promptfoo, LangSmith evals, Claude Code's own headless `claude -p` mode, Anthropic's evals framework). **Fix:** a scenario harness: 10–15 scripted decision transcripts (clear winner, 10-point close call, high-stakes flag, force-phrase paraphrase, 6 candidates requiring a bracket, user picks non-recommended) run headlessly, with structural assertions on the transcript: every `AskUserQuestion` call has ≤4 options; `(Recommended)` label matches top total; escalation occurred iff margin ≤ 15 or flags set; panel invocation preceded by escalation check. LLM-as-judge optional; structural assertions alone catch most protocol drift.

**7. Packaging/portability — VALID. Severity: Medium.**
If install is a symlink into another project, `python3 scripts/rubric.py` runs against whatever `scripts/` happens to exist in the user's cwd, or nothing. The scripts are stdlib-only so interpreter version is a non-issue in practice, but path resolution is a real break. **Fix:** in SKILL.md, reference scripts as relative to the skill directory itself — the agent sees the skill's path when the skill is loaded, so instruct: "run `python3 <this skill's directory>/scripts/rubric.py`", and state "Python ≥3.9, stdlib only." Better still, see section C: most of these scripts shouldn't exist as files at all.

### B. What the critique MISSED

Ranked by severity:

1. **The scripts formalize the deterministic step and ignore the stochastic one (Critical).** The entire Python apparatus computes things an LLM does error-free — a 4-term weighted sum, an `abs() <= 15` comparison, modular chunking. The one step with all the variance — sub-score assignment — gets no code, no anchors, no repetition. The scripts are rigor theater: they make the output *look* computed when 100% of the noise is upstream. This subsumes and deepens critique #1: the architecture has its determinism exactly inverted.

2. **"Confidence" is a category error, not just miscalibration (High).** The weighted total is a multi-criteria *utility* score (how good is this option under these weights), not a *probability* that it's best. Even perfectly calibrated, "78%" would be the wrong number to show. Showing "Score 78/100 — Contested" and "Top-2 gap: 9 points (narrow)" separately conveys both utility and genuine confidence-relevant signal.

3. **Absolute scoring without a shared reference frame (High).** Sub-scores are (per SKILL.md) assigned per-choice, sequentially, with no instruction to score all candidates in one pass against each other. LLM absolute ratings drift within and across contexts; the LLM-as-judge literature consistently finds pairwise/relative comparison more reliable than single-answer absolute scoring (Zheng et al. 2023, MT-Bench judging; this is why pairwise became the default eval mode). Fix: score all candidates in a single generation, and require the model to name, per criterion, which candidate is best before assigning numbers.

4. **Hardcoded weights are hidden assumptions steering decisions (Medium-High).** `fit_to_constraints: 0.40` regardless of whether the decision is choosing a lunch spot or an irreversible data migration. Fixed weights are defensible as a *default*, but they must be surfaced: one line in the AskUserQuestion preamble — "weights: fit 40 / reversibility 25 / evidence 20 / precedent 15, say 'reweight' to change" — turns a hidden prior into a disclosed, overridable one.

5. **No audit trail (Medium).** For a decision-support tool, the record of the decision — sub-scores, panel arguments, user's pick and any stated reason — *is* the product. Currently everything evaporates after the AskUserQuestion. Fix: one append per decision to a `.decisions.log` in the project (markdown: date, options, sub-score table, weights, escalation reason, user pick).

6. **Unguarded dependency on the `council` skill (Medium).** Step 3 invokes another skill with no versioned contract and no specified fallback if `council` isn't installed. If it's missing, the model will either improvise or silently skip — untestable, unspecified behavior. Fix: SKILL.md states the fallback ("if the council skill is unavailable, run a single adversarial self-review arguing against the current top pick and fold that in").

7. **No invalidation rule when the option set changes (Medium).** User adds a candidate via "Other," or edits one mid-flight — are existing scores comparable? Nothing says re-score all. Stale scores against fresh ones is a silent inconsistency.

8. **Default-effect steering (Medium).** `(Recommended)` label + top-position + "78% confidence" in the description is three simultaneous nudges on a UI element users already over-accept. One nudge (the label) is the feature; the other two are bugs. Mostly resolved by fix #1 in section A.

### C. Is the premise sound?

The premise — decompose a decision into fixed criteria, weight them, surface a default, escalate on genuine contention, user picks — is sound and matches both MCDA practice and what's known about LLM judgment (structured rubrics beat holistic vibes; forced structure reduces variance). Keep it.

The shape is wrong in one fundamental way: **this should be a prose protocol with at most one script, not three scripts with prose around them.** Concretely:

- Delete `panel_trigger.py` and `tournament.py` entirely. A threshold comparison and "deal 17 cards into 5 piles" are things the model does correctly in-context; as files they add a path failure mode (critique #7), a testing illusion (critique #6), and zero determinism where it matters (missed point #1).
- Keep `rubric.py` *only* if you also ship the integration harness — its real value is pinning the criteria/weights as a single source of truth, and even that can live as a table in SKILL.md.
- Rebuild the presentation layer: ordinal bands, anchors, utility-not-confidence, disclosed weights, audit log.

Patching the 7 points without this inversion leaves the system's central claim — "the total is reproducible" — false in the only sense that matters: the total is reproducible *given* sub-scores, and the sub-scores are everything.

### D. Minimum viable fix set

1. **Anchors + ordinal bands + kill the percentage.** Rewrite the rubric section of SKILL.md with per-criterion behavioral bands; present "Score band + top-2 gap" instead of "78% confidence." *Buys:* removes the automation-bias magnet and the category error — the single biggest correctness-to-effort win, and it costs zero code.

2. **Delete two scripts, validate the third, fix its path.** Remove `panel_trigger.py` and `tournament.py` (inline their trivial logic as prose rules, including the force-intent rule as "model judges intent"); add exact-key + 0–100 validation to `score_choice`; reference it via the skill directory. *Buys:* eliminates the portability break, the substring false triggers, the rigor theater, and the misleading deterministic-demo illusion in one stroke.

3. **Ship a 10-scenario headless eval harness.** Scripted transcripts with structural assertions (≤4 options per call, recommended = top score, escalation iff margin/flags, bracket behavior at N=6). *Buys:* the only test coverage that addresses the only artifact that actually executes — the prompt. Without this, every other fix is unverifiable.
